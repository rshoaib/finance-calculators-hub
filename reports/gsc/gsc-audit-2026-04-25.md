## 3. CWV findings

**Data gap this run.** The Search Console API does not expose Core Web Vitals or the Mobile Usability report — those would require either the PageSpeed Insights API or CrUX-via-BigQuery, neither of which is configured for this scheduled task. No CWV-driven fixes were applied this run, and no per-URL LCP/INP/CLS numbers are available.

**Recommendations for Rizwan** (top 3, derived from manual inspection of typical post structure rather than measured CWV data):

1. **Trailing-slash redirect cost.** Every internal link in the codebase points to the slug-without-trailing-slash form (e.g. `/savings-goal-calculator`), but the site canonicalizes to the trailing-slash form via a 308 redirect. That's a single hop, not a chain (so it's outside the SKILL's auto-fix scope), but every internal navigation pays one redirect's worth of latency. Consider adding trailing slashes to internal `<a href>` values site-wide — either via a Next.js middleware rewrite or a one-time content sweep — to eliminate the hop.
2. **Hero SVGs are inlined as the first ~200 lines of every post body.** That's render-blocking for LCP since the SVG must download as part of the HTML before the article text can paint. Consider externalizing hero SVGs into `/public/blog-images/` (Rizwan already has `hero-*.svg` files there for some posts) and referencing them via `<img>` so they can be deferred and don't bloat the HTML payload. The instruction allows adding `width`/`height` to `<img>` and removing layout-shifting wrappers; that's the right hammer once SVGs are external.
3. **Configure PageSpeed Insights API** (or wire up a CrUX BigQuery view) so future weekly audits have actual LCP/INP/CLS numbers per URL instead of this gap.

No template-level code changes were made this run (out of scope per SKILL: "Do NOT make template-level code changes autonomously").
